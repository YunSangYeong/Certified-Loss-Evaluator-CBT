# 보험·법령 문제은행 추가 요청: 진행 상태

요청 목표: 상법 보험편 500개 + 농어업재해보험법령 500개. 기존 재배·원예 1,000개 보존. 새 두 과목의 검수 완료 실제 수는 각각 0개이며 부족 수는 각각 500개다. 기존 초안 25개씩은 보존하지만 목표 완료 수에 포함하지 않는다.

## 확인된 차단

국가법령정보센터 상법 및 농어업재해보험법 원문에 새 요청을 보냈으나 모두 `curl exit 56: CONNECT tunnel failed, response 403`, 원격 HTTP 미수신(000). 실행 환경은 restricted이고 법령 도메인이 허용 목록에 없다. 환경 설정 초안 조회도 `The current environment draft could not be verified` 오류로 확인되지 않아 알 수 없는 기존 목록을 덮어쓰지 않았다.

필요한 추가 도메인: `www.law.go.kr`, `law.go.kr`. 네트워크 허용 후 실제 문서를 열어 시행일·개정 내용·시험 적용 범위를 확인해야 한다. 접근 설정만으로 법령 검증 완료가 되는 것은 아니다. GitHub Pages 접근이나 배포 재시도는 이번 요청의 선행 조건이 아니다.

## 작성·검토 방식

1. 시행일이 명시된 공식 법률·하위 법령·관련 고시를 확보하고 실제 시험 범위를 대조한다.
2. 과목별 500개는 정의·요건·효과·예외·사례 적용을 나누어 자체 작성한다. 같은 정답의 질문 바꿔쓰기를 독립 문항으로 부풀리지 않는다. 사례·숫자 변형은 family와 실제 유형 수를 공개한다.
3. 각 문항에 단원·5개 보기·정답·해설·시행일·조문·열람일·원문 발췌·정답 판단 근거를 연결한다. 기출이 아니므로 기출 연도·회차는 null이다.
4. 정답과 네 오답을 조문 및 예외 규정에 대조한다. 모호하거나 개정 여부를 확인하지 못한 문항은 pending으로 제외한다. 구조 검사 통과를 법률 내용의 검증이라고 부르지 않는다.
5. 기존 ID와 기록을 보존하고 중복·의미 중복을 검토한다. 기본 은행에 실제 검토 완료 문항 500개씩을 등록한 뒤 과목별 25개 추출로 실전시험을 검증한다. 출시/배포는 별도이며 첫 차단 중단 규칙을 유지한다.

조문 구조와 범위 확인 전 문항 배분을 확정하지 않는다. 이전 초안에 법령 근거를 사후로 허위 부여하거나 재배·원예 계산 문항의 과목명만 변경하지 않는다.

## 준비한 검사

`python scripts/audit_legal_bank.py src/data/questions.json src/data/drafts.json --require-targets`

이 명령은 현재 의도적으로 실패해야 한다. 과목별 검수 완료 0/500, 검증 대기 25개씩을 보여준다. 검수 완료 법령 문항에는 `legalReview`의 `statute`, `article`, `effectiveDate`, `retrievedAt`, `sourceUrl`, `sourceExcerpt`, `answerReason`, `reviewNote`를 요구한다. 공식 HTTPS 주소 및 날짜 형식·중복·보기·정답·기출 메타데이터를 검사한다. 법적 정답과 실제 원문 열람은 사람이 별도 확인해야 하며 검사 도구가 이를 보증하지 않는다.
